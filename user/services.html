Using Services¶

Let’s start off with using a simple service in cula, the UPower service. We will properly cover the event system, and the common patterns too along with the implementation of this service.

Every service definition headers are provided at libcula/services/*.h. So, the upower service header is at libcula/services/upower.h.

Service Creation¶

Creating the service is simple. You just have to call the cula_create_upower(ctx) function, which returns a struct cula_upower.

On creation itself, it will come with a population data field:

struct {
    double percentage;
    bool on_battery;
} data;

You can access these to get the current state fetched by the cula UPower service.

Event System¶

We have went over a brief of the event system before. But this section will cover all that is to the event system.

Attaching to Signal¶

The struct cula_upower has a events field which contains all the events supported by the service:

struct {
    cula_signal_t percentage_changed;
    cula_signal_t on_battery_changed;
} events;

You can create your cula_listener_t and hook into a signal with cula_signal_add like so:

1// ctx = cula context;
2struct cula_upower *upower = cula_create_upower(ctx);
3
4cula_listener_t *listener = calloc(1, sizeof(cula_listener_t));
5listener.notify = callback_function;
6
7cula_signal_add(upower->events.percentage_changed, listener);

Here we are heap allocating a listener to attach the event to. Instead of that, we highly recommend you create a dedicated structure where you will store your listeners. This way, you only have to calloc that structure, and all the listeners will be initialized. There is also a bonus benifit to it, which I will get to soon after this example:

 1struct upower_wrapper {
 2    cula_listener_t perc;
 3    // store any other data you want here
 4};
 5
 6// initialize only once
 7struct upower_wrapper *upower_wrap = calloc(1, sizeof(struct upower_wrapper));
 8
 9// then use all the listeners freely
10upower_wrap->perc.notify = /* .. */;
11cula_signal_add(/* .. */, upower_wrap->perc);

Callback Function¶

We have discussed how we can create the servie and how we can hook into an event. Now lets discss how you handle things inside the callback function you attached to .notify.

Note

All callbacks must be of the signature (cula_listener_t *listener, void *data).

1void callback_function(cula_listener_t *listener, void *data) {
2    struct upower_wrapper *upower_wrap = 
3        cula_container_of(listener, upower_wrap, perc);
4
5    // data can be casted into the appropriate type.
6}

cula_container_of is the highlight here. It is inspired by wl_container_of from wayland, which can be used to retreive a pointer to the parent structure from a member name.

// p1: pointer to listener
// p2: pointer to data to create
// p3: member of parent
cula_container_of(p1, p2, p3);

Warning

The third parameter (member of parent), should be the cula_listener_t member to who’s .notify you attached the callback to.

This is why we recommended you to use a structure instead of calloc’ing a listener when needed. You can hold other data too like pointer to a global structure where you store all the data.

Full Example¶

Here is the full example with recommended parctices followed.

 1#include <stdio.h>
 2#include <stdlib.h>
 3#include <libcula/core.h>
 4#include <libcula/utils.h>
 5#include <libcula/services/upower.h>
 6
 7// Structure for storing upower service events
 8struct upower_handler {
 9    cula_listener_t percentage;
10    // other service data here...
11};
12
13void percentage_notify(cula_listener_t *listener, void *data);
14
15int main() {
16    struct cula_context *ctx = cula_create_context();
17    if (!ctx) {
18        printf("Failed to create context!\n");
19        return 1;
20    }
21
22    cula_run_context(ctx);
23
24    // Ideally, store this ctx somewhere now.
25
26    /** 
27     * Create the service structure.
28     * We are heap allocating it with 'calloc' to preserve it beyond
29     * the end of this function. Make sure to free it during shutdown.
30     */
31    struct upower_handler *upower_handler = calloc(1, sizeof(struct upower_handler));
32
33    // Now lets create the service.
34    struct cula_upower *upower = cula_create_upower(ctx);
35    
36    // On creation itself, the upower service will fetch
37    // all the initial data. You can access it directly here.
38    bool is_on_battery = upower->data.on_battery;
39    bool is_lid_closed = upower->data.lid_closed;
40    bool is_lid_present = upower->data.lid_present;
41
42    // Now, we can link to the events
43    upower_handler->percentage.notify = percentage_notify;
44    cula_signal_add(&upower->events.on_battery_changed, &upower_handler->percentage);
45
46    // Shutdown
47    cula_list_remove(&upower_handler->percentage.link);
48    free(upower_handler);
49    cula_destroy_context(ctx);
50
51    return 0;
52}
53
54void percentage_notify(cula_listener_t *listener, void *data) {
55    struct upower_handler *upower_handler = 
56        cula_container_of(listener, upower_handler, percentage);
57
58    // The data can be anything. Make sure to check the API documentation
59    // of the event to know which structure it provides, if it provides any.
60    // UPower Service passes the 'cula_upower' as data.
61    struct cula_upower *upower = data;
62
63    // The upower->data now contains fresh data. Do whatever with it,
64    // like storing it in a structure. This is why we recommended using
65    // a dedicated structure (like upower_handler) instead of calloc'ing a 
66    // new 'cula_listener_t' every time.
67}
